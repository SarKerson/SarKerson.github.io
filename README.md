## 写作约定

文章题名统一使用 `领域：具体主题`。Weekly 使用 `W周次｜本期核心主题`，周次按覆盖周的 ISO 自然周编号计算；年份、完整覆盖日期和修订日期保留在正文及按年归档中。系列序号留在目录，历史补刊不重算周次。

先讲清问题，再展开机制、证据和取舍。图用于解释结构、流程或结果；不靠装饰填充内容。

引用研究时，区分作者报告、源码事实和我的推断。数字交代任务、模型、基线与成本；未独立复现，就明确写出。工程建议给出适用条件和失败边界。

阅读记录可以保留在笔记里。进入博客的文章需要有明确主线和自己的判断；Weekly 按真实覆盖周期组织，新作与补遗分开，质量不足时减少篇数。

## 文章与站点维护

站点使用 Jekyll、Markdown 与 Liquid。文章放在 `_posts/`，文件名使用 `YYYY-MM-DD-slug.md`；`_config.yml` 保存站点配置，`_layouts/` 与 `_includes/` 保存页面模板，图片放在 `img/`。

新文章的最小头信息：

```yaml
---
layout: post
title: "Agent Skills：有效性评测与收益归因"
subtitle: "一句话说明问题"
date: 2026-10-12 10:00:00 +0800
author: Eric.Y
catalog: true
tags:
  - Agent
  - Skills
---
```

配置好本地 Jekyll 环境后，可运行 `jekyll serve` 预览。仓库目前没有锁定的 Gemfile；本地依赖版本需要另行配置。

从 Notion 整理到博客时，先转换表格、折叠块和页面引用，再检查图片与参考链接。附件应使用可长期访问的地址；不要将临时签名图片链接直接写入文章。完成页面预览和内容审核后再发布。
